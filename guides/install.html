Setting up a new Mac

One pasted line does the lot. A bare Mac reaches a working shell in under three minutes, plus however long the apps take to download.

The one command

Open Terminal on the new Mac and paste this. It downloads a script called script/bootstrap and runs it.

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/shaneog/dotfiles/HEAD/script/bootstrap)"

In plain words

Bootstrap is a moving crew with a checklist. It asks for your password once at the door, then works through the list in order: fetch the tools, bring the boxes in, put things where they belong, set the thermostat, stock the shelves. If any step fails it stops and tells you which.

What happens, in order

Every step below is real code in script/bootstrap or a script it calls. The label on each one says which.

Two things only you can do

Everything above is automatic. These two are not, because they involve your identity. Bootstrap ends by naming whichever of them is still missing.

  • By hand · required

    Create ~/.gitconfig-user

    Your name, your email and the public half of your signing key. Commit signing is always on, and this file is where git learns which key to use. Type it yourself, or let make identity write it from 1Password.

  • By hand · once

    Turn on the 1Password SSH agent

    In 1Password, open Settings, then Developer, and tick “Use the SSH agent”. Keys and 1Password explains why.

# ~/.gitconfig-user
[user]
	name = Your Name
	email = you@example.com
	signingkey = ssh-ed25519 AAAA...   # the public key, not a path

Or have 1Password write it

If you keep those three values in 1Password, one command writes the file. It comes after bootstrap, not during it, because on a new Mac you have to open the 1Password app and sign in first. In its settings, under Developer, switch on “Integrate with 1Password CLI” as well.

make identity
In 1PasswordWhat it holds
An item called Git identityAny kind of item will do. A secure note is the plainest.
A text field called nameYour name as it should appear on a commit.
A text field called emailThe address to commit with.
A text field called signingkeyThe public key, copied from your SSH key item.

It is optional, and careful. If 1Password is not signed in, or has no such item, it tells you and writes nothing. If the file is already there it leaves it alone, unless you run script/identity --replace. It refuses a private key. To read a different item, name it: script/identity "Another item".

How long it takes

These numbers come from the virtual machine test, which installs onto a completely fresh copy of macOS. The first bar includes Apple's Command Line Tools, which Homebrew installs before anything else. Apps are left out because their download time depends on your connection. This chart is the one place these timings are kept.

Running it again is safe

Bootstrap is written so a second run only does what is still missing. It still asks for your password, though, so for a Mac that is already set up there is a lighter command.

StepOn a Mac that is already set up
HomebrewFound, so the installer is skipped.
DotfilesPulled instead of cloned. Local edits are stashed and put back.
LinksEach one already points into the repository, so it is reported as unchanged.
macOS settingsEach setting is read first and only written if it differs. The record of the original values is never overwritten, and the Dock's icons are not cleared a second time.
BrewfileChecked first. Nothing is installed if nothing is missing.
Login shellAlready Homebrew's zsh, so it is left alone.
macOS settings, second lookNothing is left to apply, so nothing runs, and the Dock and Finder are not restarted.

Installing from somewhere else

Three variables change where the dotfiles come from. That is handy for trying a branch or a fork, or for a Mac that has no GitHub login yet and gets the repository from a USB stick.

DOTFILES_REF=some-branch ./script/bootstrap
DOTFILES_URL=/Volumes/stick/dotfiles ./script/bootstrap
GITHUB_USER=someone ./script/bootstrap    # github.com/someone/dotfiles

DOTFILES_REF only counts for a fresh copy. When ~/.dotfiles is already there, it is pulled on whichever branch it has checked out.

Keeping a Mac up to date

Once a Mac is set up, two commands look after it. Run them from ~/.dotfiles.

make update
make doctor
  • make update

    Catch up with the repository

    • Pulls the latest dotfiles. Local edits are stashed and put back.
    • Runs script/setup, so a config that is new gets its signpost.
    • Installs anything the Brewfile lists that is missing.
    • Puts Neovim's plugins at the versions in the lockfile.

    It never asks for a password. Homebrew itself, the login shell and the macOS settings stay bootstrap's job.

  • make doctor

    Ask whether this Mac is healthy

    • Is every signpost still in place?
    • Is this copy behind the one on GitHub?
    • Are ~/.gitconfig-user and the 1Password agent there?
    • Has a macOS setting drifted, or is something in the Brewfile not installed?
    • Has a shell file that another tool manages changed?
    • Has the virtual machine test passed lately?

    It only reports. A missing signpost, file or agent is a failure. Everything else is a warning. To see whether this copy is behind, it asks GitHub and downloads nothing.

Skipping is not passing

When the doctor cannot run one of its checks, for example because the Mac is offline, it prints NOT CHECKED and says which. It never reports a check it skipped as a check that passed.

When another tool rewrites your shell files

On some Macs another tool owns ~/.profile, ~/.bashrc, ~/.zprofile and ~/.zshrc, and rewrites them when it likes. These dotfiles read those files first and then add their own on top, so a rewrite can change how your shell behaves without anything here changing.

The doctor watches for that. The first time it sees one of those files it makes a note of its fingerprint, a short code that changes whenever the file does. On later runs it tells you which files no longer match, and it keeps telling you until you accept them:

script/doctor --accept

That note is the only thing the doctor ever writes. It holds fingerprints, not the files, it stays on that Mac, and the doctor never prints what the files say. On a Mac with none of the four files there is nothing to watch, and it says nothing.

Taking it all out again

script/remove is the undo. It asks “Are you sure?” first, and by default it only removes what this repository put there.

  • script/remove

    The dotfiles

    • The login shell goes back to /bin/zsh.
    • The shell's caches are deleted.
    • ~/.dotfiles is deleted, and so is every signpost in your home folder, ~/.config and ~/.ssh that pointed into it. A signpost that was already broken belongs to something else and is left alone.
  • script/remove --everything

    The dotfiles and Homebrew

    • All of the above.
    • Every package and app Homebrew installed.
    • Homebrew itself, and the Command Line Tools. A full Xcode is never touched.
  • Either way

    Left alone

    • Your shell history.
    • Every other app's files in ~/.config and ~/.ssh.
    • The macOS settings. To put those back, run the restore script that script/macos saved in ~/.local/share/dotfiles/macos-defaults on its first run.

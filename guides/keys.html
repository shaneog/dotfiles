Keys, 1Password and a fingerprint

There is no private key file anywhere on these Macs. Logging in to servers, signing commits and running sudo all end at the same place: a Touch ID prompt.

The key never leaves the vault

An SSH key proves who you are to a server, and to GitHub. The usual setup keeps that key as a file in ~/.ssh, where any program running as you can read it. This repository's rule is stricter: no private keys on disk, ever.

In plain words

Most people keep the house key under the doormat. Here the key is locked in a safe (1Password) with a guard beside it (the 1Password agent). When something needs the key, the guard does not hand it over. The guard walks to the door, unlocks it, and comes back, after checking your fingerprint.

Three jobs, one fingerprint

Logging in: two doors to the same guard

Programs find the agent in two different ways, so the repository sets both. Each covers programs the other misses.

WhereWhat it setsWho it is for
ssh/configIdentityAgent, for every hostAnything that runs ssh, including apps that were never started from a shell.
config/zsh/lib/1password.zshThe SSH_AUTH_SOCK variableTools that talk to an agent directly and never read the SSH config file.

One exception

When you connect to one of these Macs over SSH, nobody is sitting at it to touch the sensor. Both settings notice the incoming session and step back, so the keys you brought with you from the other computer are used instead.

The rest of the SSH settings

  • This Mac's own hosts come first. ~/.ssh/config-local is included at the top, because SSH keeps the first value it sees for each setting.
  • Connections are shared. While one connection to a server is open, a second one reuses it and opens instantly.
  • Short network drops are forgiven. A connection survives about five minutes of silence before it gives up.
  • Unknown servers are questioned. SSH asks before trusting a server it has not seen before.

Signing: proof a commit is yours

Anyone can type any name into a commit. A signature is what proves a commit really came from you, and it is what puts the “Verified” badge on GitHub.

Signing is switched on for every commit in config/git/config. The one piece that differs per Mac is which key to sign with, and that lives in ~/.gitconfig-user, the file you create by hand.

# config/git/config, shared by every Mac
[gpg]
  format = ssh
[gpg "ssh"]
  program = "/Applications/1Password.app/Contents/MacOS/op-ssh-sign"
  allowedSignersFile = ~/.config/git/allowed_signers
[commit]
  gpgsign = true

# ~/.gitconfig-user, private to one Mac
[user]
  signingkey = ssh-ed25519 AAAA...   # the public half

The one thing to remember

If ~/.gitconfig-user is missing, git has no key to sign with and commits cannot be signed. It is the only file a new Mac has to be given by hand.

Checking works the other way round. config/git/allowed_signers lists the public keys this repository trusts, so git log --show-signature can say whether each commit was signed by one of them. Public keys are safe to publish, which is why that file is tracked.

Touch ID for sudo

script/macos sets sudo up to accept a fingerprint. This replaces the password prompt. It does not remove the check: you still have to approve every time.

  • Why a bridge

    tmux hides the screen

    A shell inside tmux cannot reach the desktop, so the fingerprint prompt would never appear. A small module called pam_reattach bridges back to it.

  • Why a copy

    Only root may change it

    Anything sudo loads runs as root. So the module is copied to a folder only root can write to, and the script refuses if any folder on the way there could be changed by someone else.

  • Upkeep

    Re-run after an upgrade

    After brew upgrade pam-reattach, run script/macos again to refresh the copy. script/macos --check reports when it has fallen behind.

A public repository with nothing to hide

The repository is public, so three rules keep private things out of it.

  • Secrets are scanned for. The test suite runs a secret scanner over the whole git history.
  • Only public keys are tracked. The private halves never leave 1Password.
  • Private names stay local. Per-Mac files and machine-specific paths are kept out of git, as Where files live describes.

Where the files live

The real files stay in one folder, ~/.dotfiles. Your home folder holds signposts that point at them, one for each tool.

Signposts, not copies

Tools expect their settings in fixed places: git looks in ~/.config/git, SSH looks in ~/.ssh/config. Copying files there would mean two versions that drift apart. So script/setup creates symlinks instead.

In plain words

A symlink is a signpost. When git walks up to ~/.config/git it finds a sign that says “the real folder is in ~/.dotfiles/config/git”, follows it, and never notices the detour. Edit the file from either side and you are editing the same file.

The rule behind the map

script/setup walks the top level of the repository and does one of two things with what it finds.

  • A file becomes a signpost named ~/.<name>. That is how Brewfile becomes ~/.Brewfile.
  • A folder, which means config and ssh, becomes a real folder, ~/.config or ~/.ssh. Inside it goes one signpost for each thing git tracks directly inside the repository's folder.

Then it adds ~/.zshenv, because that one file has to sit in the home folder for zsh to find it. The repository's own scaffolding is skipped, so it never shows up in your home folder: script/, test/, guides/, the Makefile and anything ending in .md or .txt.

Why one signpost per tool

Dozens of apps keep their settings in ~/.config, and most of them have nothing to do with this repository. With one signpost per tool, their files stay in your home folder. They cannot be published by accident, and removing the dotfiles cannot delete them.

Adding a tool

Git's list of tracked files is the list of what gets linked. To bring a new tool's settings into the repository, put them under config/, git add them, and run script/setup again.

What if something is already there?

A Mac that has been used for a day already has files in these places. Setup never deletes what it finds. It picks one of three polite options.

Coming from the older layout

Earlier versions made ~/.config and ~/.ssh signposts to the repository's whole folders, so every app was writing inside the repository. On a Mac set up that way, pull the latest changes and run script/setup once. It moves everything git does not track back out into real folders at the same paths, then links one entry at a time as above.

Four files it never touches

On a managed Mac, another tool owns ~/.profile, ~/.bashrc, ~/.zprofile and ~/.zshrc, and rewrites them from time to time. Setup neither creates nor changes any of the four. They are read as a base layer instead, which Opening a terminal explains.

Why the ignore list is upside down

Here is a side effect of the signposts. Because ~/.config/gh is the repository's config/gh folder, anything the GitHub CLI saves there lands inside the repository, including its record of who is logged in. Left alone, git would offer to publish it.

So .gitignore works like a guest list. It starts by ignoring everything under config/ and ssh/, then names the few things that are allowed in.

# everything is turned away at the door...
config/*
ssh/*

# ...except the names on the list
!config/git
!config/zsh/
!config/nvim/
!ssh/config

Good to know

A test checks that every folder under config/ has been decided on purpose: either tracked, or ignored by a rule of its own. A folder that simply appeared fails the test, so nothing gets published or forgotten by accident. Names that should not appear in a public repository go in .git/info/exclude, which is never shared.

Three files that belong to one Mac

Some settings are different on every machine and must not be shared. Each tracked file has an untracked partner for exactly that.

Private fileAdds toWhat goes in it
~/.gitconfig-userconfig/git/configYour name, email and signing key. Required, and the only file you create by hand.
~/.ssh/config-localssh/configHosts only this Mac knows about. Setup creates it empty. It is read first, so it wins.
~/.zshrc.localconfig/zsh/.zshrcShell tweaks for this Mac only. Optional, and read last, so it has the final word.

Three drawers for everything else

One of the first things the shell does is name three folders. Every tool in this setup is told to use them, which keeps the home folder itself nearly empty.

  • ~/.config

    Settings

    Written by a person. The entries this repository owns are signposts into its config/ folder, tracked in git.

  • ~/.cache

    Throwaway

    Things the shell worked out once and saved to go faster, such as the completion index. Safe to delete at any time.

  • ~/.local/share

    Yours

    Data worth keeping that is not a setting: shell history, installed plugins, saved tmux sessions.
